# powertokens-kit 使用说明与接口 / 能力清单

> 生成日期 2026-11-18 · 对应版本 Node 核心包 **v0.8.7** · 仓库 `tjj1234/powertokens-kit`
> 依据源码实读：`node/index.js`、`node/account-client.js`、`pt-gateway/account_client.py`、`pt-gateway/recheck.py`、`pt-gateway/validate_catalog.py`、各 `README.md`。事实口径见 [SSOT](PT_项目资料总集_20261112.md) §12–§21。

---

## 0. 一句话看懂这个 kit 是什么

**它不替你发模型请求，也不生成视频/图片。** 它做两件事：

1. **规则层**（`node/index.js`）：零依赖、不联网，只读一份 `catalog.json`，告诉 Agent「该选哪个模型、报错了该怎么办、要不要重试、思考参数怎么传」。
2. **账户只读客户端**（`account-client.js` / `account_client.py`）：连 PT 账户域，查余额、查 Key 状态、查消费记录、查可见模型、**做费用预估**——全部只读或计费探针，不发生成请求。

真正的模型调用由 DSH / 你自己的供应商层去做。kit 是「决策大脑 + 记账本」，不是「发动机」。

## 1. 怎么装、怎么引入

### 1.1 开发态（在仓库里）

```js
const core = require('./node');                         // 规则层
const { AccountClient } = require('./node/account-client'); // 账户客户端
```

规则层默认读仓库同一份 `../pt-gateway/catalog.json`（与 Python 工具链共享），无需另存模型表。

### 1.2 离线分发（放进 DSH 的 vendor/）

```bash
cd node && npm pack          # 生成 dist/powertokens-kit-core-0.8.7.tgz
```

tgz **自包含**：内含 `index.js` / `account-client.js` / `catalog.snapshot.json` / `catalog.schema.snapshot.json` / `README.md` / `package.json`。把解包后的 `package/` 整个放进 `vendor/` 即可，不依赖 `pt-gateway/` 目录；`loadCatalog()` 检测不到仓库 catalog 时自动回退读包内快照。零运行时依赖，Node ≥ 18。

### 1.3 凭证（重要）

- 两套凭证**不可混用**：
  - 账户域 `https://powertokens.ai/api` → 裸 `pt_live_...` 个人令牌（**不带 Bearer**）+ 数字 `key_id`。
  - 生成域 `https://api.powertokens.ai/v1/models` → `Bearer <模型 API Key>`。
- 凭证**由调用方每次传入**，客户端不读配置文件、不落盘、不写日志。可用 `AccountClient.fromEnv()` 从 `PT_ACCESS_TOKEN` / `PT_KEY_ID` 读取。
- `key_id` 请求侧必须是**数字**；PT 没有「用 API Key 反查 key_id」的接口。
- 账户域业务成功只看响应体 `code`（无效凭证会返回 **HTTP 200 + code=500**，只看 HTTP 状态会误判成功）。

## 2. 规则层 API（`node/index.js`，5 条主 API + 辅助）

| API | 作用 | 关键返回 |
|---|---|---|
| `loadCatalog({path, expectedSchema})` | 固定版本 + 格式校验；失败抛 `CatalogValidationError`，调用方应继续用上一版本 | catalog 对象 |
| `selectCandidates(purpose, keyModels, opts)` | **AUTO**：按用途有序返回候选，应用 4 条跳过规则；**PINNED**：用户指定模型只判定可用性、绝不自动换 | AUTO `[{id,position,kind,channel}]`；`detail:true` 得 `{purpose,candidates,skipped,pending_verification,matched_by}`；PINNED `{pinned,available,reasons,checks,candidate}` |
| `classifyError(status, body, opts)` | 把 HTTP 状态 + 响应体归到 `errors` 9 类；未收录按「不重试、换模型、上报」 | `{category,agent_action,retryable,switch_model,compact,matched_by,...}` |
| `retryDecision(input, opts)` | 给重试 / 换模型 / 停止决策，支持 pinned、退避、次数上限 | `{action,accepted,settled,charged,delay_ms,reason_code,pinned,...}` |
| `reasoningParams(model, effort, opts)` | 思考模式传参；`effort='none'` 返回 `value:null + needs_confirmation:true`，**不猜关闭取值** | `{supported,param,value,default_enabled,needs_confirmation,...}` |

辅助导出：`catalogVersion()`（透出 `schema / updated / kit_version / path`，可与 CHANGELOG 对账）、`isKnownValue()` / `isKnownSource()`（null 或 `inferred`/`configured` 一律按未知）、`isGenerationModel()`、`CatalogValidationError`。

### 2.1 4 条跳过规则（`selectCandidates`）

已 `delisted` / `tool_calling.verified === false`（`null` 不跳过）/ 搜索用途且 `works` 或 `returns_sources` 为 `false` / 不在本 Key 的 `/v1/models` 可见列表。
注意：`not_in_key_view` **不等于**下架；`null`（未实测）一律不跳过。搜索用途只有 `works===true && returns_sources===true` 才进 `candidates`，`null` 进 `pending_verification`。

### 2.2 `retryDecision` 分支优先级（0.8.4 固定）

**发送前视觉拦截 → 受理未知 → 2xx 已受理不重放 → 上下文超长 → 其余。**

- 2xx（含流中途报错、含 body 带 `context_length_exceeded`）一律 `action:'none'`，绝不 compact / retry / switch——避免重复扣费。
- 无有效 HTTP 状态（超时 / 断网）→ `stop` + `acceptance_unknown`，绝不重发（PT 可能已受理）。
- 非 2xx 的上下文超长（400/422）→ `compact`（先压缩再发，不原样重试）。
- `maxRetries:0` 合法（不重试），只有参数未传才用默认 3。

### 2.3 用户指定模型（pinned）

`selectCandidates(purpose, visible, {pinnedModel:'gpt-5.2', hasImage})` 只判定可用性；`retryDecision({pinned:true, model, status, attempt})` 出错时只重试同一模型、耗尽后 `stop`，不返回换模型。不可用/无权限/参数不支持 → `user_choice`，交用户决定。

### 2.4 快速上手

```js
const { loadCatalog, selectCandidates, classifyError, retryDecision } = require('./node');
const cat = loadCatalog({ expectedSchema: 2 });
const visible = await yourModelsCall();                 // 该 Key 的 /v1/models 可见 ID
const cands = selectCandidates('general', visible, { catalog: cat, detail: true });
const err = classifyError(429, { error: { code: 'model_rate_limited' } });
const d = retryDecision({ status: 429, attempt: 1, retryAfter: 5 });
```

## 3. 账户只读客户端（`account-client.js` / `account_client.py`）

两侧方法一一对应（Node 驼峰 / Python 下划线），全部只读或计费探针。

| 能力 | Node 方法 | Python 方法 | 端点 | 说明 |
|---|---|---|---|---|
| Key 状态 | `getKeyStatus(keyId)` | `get_key_status()` | `POST /v1/key/info` | body 传整数 `key_id`；GET 或不带 `/v1` 都是 404 |
| 余额 | `getBalance()` | `get_balance()` | `GET /v1/billing/balance?key_id=` | `key_id` 必填数字；金额保留 `credits`，不换算 USD |
| 消费记录列表 | `listUsageRecords({startDate,endDate,keyId})` | `list_usage_records()` | `GET /v1/billing/usage` | `key_id` + 起止日期三者必填；日汇总有延迟 |
| 单条消费记录 | `getUsageRecord({requestId,taskId,consumeId})` | `get_usage_record()` | `GET /v1/logs/query` | **按 ID 精查单条，不是列表接口**；三键任一必填 |
| **费用预估** | `estimateCost({model,endpoint,request,keyId,kind})` | `estimate_cost()` | `POST /v1/billing/estimate` | **见第 4 节** |
| 资产库协议状态 | `getAgreementStatus()` | `get_agreement_status()` | `GET /v1/asset/agreement/status` | 只看 `agreement_accepted`，忽略 `asset_library_enabled` |
| 可见模型 | `getKeyModels(apiKey)` | `get_key_models()` | `GET /v1/models`（生成域） | `Bearer` 鉴权，返回本 Key 可见视图 ≠ 全量清单 |

`getUsageRecord` 的「未查到」三态（0.8.6，仅此接口）：有效记录 `found:true`；明确未找到 `found:false, category:'record_not_found'`；200 空壳 `found:false, category:'empty_record'`；其他错误 `found:null`。对账只读结构化 `found`/`category`，**不解析 PT 的 msg**；`found:false` 不代表未扣费、不可据此重发。

统一安全加固（0.8.3–0.8.4）：账户域 2xx 必须是合法 JSON 且 `code` 为明确成功值（`200/'200'/0/'0'`），否则 `invalid_response`；`data_as_of`/`is_cached` 只透传服务端值、无则 `null`；支持 `AbortSignal` 取消；响应大小上限默认 1 MiB。

### 3.1 快速上手

```js
const { AccountClient } = require('./node/account-client');
const acct = AccountClient.fromEnv();   // 读 PT_ACCESS_TOKEN / PT_KEY_ID
const bal = await acct.getBalance();     // { ok, code, data, error, data_as_of, is_cached }
if (!bal.ok) console.error(bal.error.category);
```

## 4. 是否包含预估接口？—— 有，且是官方接口

**结论：包含。** `estimateCost()` / `estimate_cost()` 就是费用预估接口，走 PT 官方 `POST /v1/billing/estimate`。

要点（均为实测 / 官方口径，见 SSOT §12.3、§15.4）：

1. **不扣费**：真机实测余额 `80 → 80 credits`（T6 整包被接受、确认不计费）。
2. **整包请求体**：`{ model, endpoint, key_id, request:{...} }`，`key_id` 必填且为数字。
3. **不支持对话模型（chat）**：chat 在本地被拦截、不发请求，返回 `error.category:'unsupported'`；因为 `/v1/models` 不含价格，chat 费用**以实际扣费为准**，不自建单价表。预估主要面向图 / 视频类。
4. **金额保留 credits**，不换算 USD（1 USD = 1000 credits 固定）。
5. **预估值只是参考**：U10 裁决「以实际扣费为准」，实测 `wan3.0-video` 5s/720p 预估 1000 credits vs 实扣 500 credits，`catalog.pricing_policy` 明确「预估可能偏高，只作参考」。

> 补充：真正扣费的单价真相源是消费记录 `logs/query`；`GET /v1/billing/usage` 当日不实时计入消费（N7）。

## 5. Python 工具链（校验 / 复核 / 测试）

| 工具 | 命令 | 作用 |
|---|---|---|
| catalog 校验 | `python pt-gateway/validate_catalog.py` | schema / 字段 / 来源枚举守门，改 catalog 后必跑 |
| 复核脚本 | `python pt-gateway/recheck.py` | 离线对账（0 花费）；`--live-view <models.json>` 对账 `top_provider` 上下限；`--registry` 生成待复核清单 |
| 真机复核 | `recheck.py --live --max-usd <N> --usd-per-1k-tokens <N>` | 真实调用 chat/completions，**会产生费用**；`--max-usd` 是硬上限，必须 > 0，未显式给出则不跑 |
| 单元测试 | `python pt-gateway/tests/run_tests.py` | Python 侧全量 |
| Node 测试 | `cd node && npm test` | `node --test`，**62/62**（0.8.7），0 花费 |

`--live` 与 `--max-usd` 的设计遵守安全边界：默认离线、0 花费；任何会产生费用的调用必须显式给出预算上限。

## 6. 能力边界（明确不做什么）

- 不发模型生成请求、不做媒体生成（视频 / 图片由供应商层负责）。
- 不做客户端权限拦截（fail-open）；某 Key 能否调用某模型以该 Key 的 `/v1/models` 与服务端报错为准。
- 字段为 `null` 或来源为 `inferred` / `configured` 一律按未知处理。
- 不保存凭证；令牌只在内存 / 本机临时文件，用完即删。
