# remake 网站方案：以 PT 为生成+理解引擎，开源只补下载与合成

> 研究结论文档（未动代码）。目标：复刻 media.io 的 Viral Studio——用户输入一个视频链接，网站自动 remake 出一条新视频。
> 硬约束：① 生成步**必须通过 PT 模型**；② 其余环节尽量走 PT；③ **无 GPU**（本地大模型路线关闭）。
>
> ⚠️ **更正（2026-11-03）**：早期版本误判"PT 只覆盖视频生成、其余 6 步不能走 PT"。核实 PT 官网模型页后修正——**PT 平台还提供 chat/LLM 与多模态视觉+视频理解**，因此 ②③④⑤ + 图像 + TTS 均可走 PT。本文为修正后的准确版本。（注：此前做的 `powertokens-video` 仓库只包了视频+计费，不等于 PT 平台全貌。）

---

## 0. 一句话结论

**可以做，而且比你之前担心的更接近"全部走 PT"。**

PT 平台经统一 API 提供：视频生成、图像生成、音频/TTS、**chat/LLM（OpenAI 兼容）**、**多模态视觉+视频理解**。所以 7 步里 **②③④⑤ + 图像 + TTS 都能走 PT 云端**——你这边**零 GPU、零本地模型**。真正绕不开开源/自研的只剩 3 步：① 下载（yt-dlp）、⑥ 合成（FFmpeg）、⑦ 发布（平台 API，MVP 可砍）。

## 2. PT 能力边界（修正后，诚实划界）

PT 平台当前覆盖：**视频生成、图像生成、音频/TTS、chat/LLM、多模态视觉+视频理解、账户/计费查询**。

PT **不覆盖**：下载外部视频、把多段成片合成时间线+烧字幕+重排比例（NLE 级合成）、社媒发布。

→ "全部通过 PT 接口完成"**仍差 ①③⑥⑦ 这几步**（下载/合成/发布天生不是模型能力）；但**"生成+理解+改写+转录全部走 PT、其余开源只补下载与合成"**已高度满足你"必须通过 PT 模型"的要求，且远非早期误判的"只能生成"。

> ASR 说明：PT **没有专门的语音转文字端点**，但其多模态 chat 模型可接收音频/视频输入并按提示转写。对长视频，分片喂给 Qwen3.8 Flash 即可；若追求工业级词级时间戳/说话人分离，再退回 faster-whisper 兜底。
>
> 前瞻性：若 PT 未来暴露专用 ASR/转录端点，② 的兜底也能一并换成 PT。

### 2.1 假设 PT 补齐「ASR / TTS / OCR / Embeddings / Rerank / 实时语音」这 5 类能力后

把新能力逐一对回 7 步管线（见第 1 节）：

| 新增能力 | 对应 remake 步骤 | 作用 | 是否 remake 必需 |
|---|---|---|---|
| **ASR**（`/v1/audio/transcriptions`） | ② 转录 | 取代「多模态 chat 凑合转写」，给工业级词级时间戳+说话人分离 | ✅ 必需 |
| **OCR**（`/v1/document` 类） | ③ 结构分析 | 抽视频帧里出现的文字/标题/字幕轨，补足多模态对画面文字的盲区 | ⚠️ 锦上添花 |
| **TTS**（`/v1/audio/speech`，PT 当前已有通道） | ⑤ 后处理 | 生成全新配音/旁白（支持换语种、换声线），让 remake 不只是换画面 | ⚠️ 锦上添花（增强项） |
| **Embeddings / Rerank** | ④ 改写前后 | 风格/参考镜头的语义匹配、RAG 增强提示词复用 | ❌ 非必需（MVP 可不要） |
| **实时语音** | — | 实时对话/直播配音，异步 remake 用不上 | ❌ 无关 |

**结论**：补齐这 5 类后，PT 将覆盖 **② ③ ④ ⑤ 全部 AI 推理步骤**（且 ② 从"凑合"变"专业"、⑤ 还能顺带配 TTS 配音）。

但「**整个** remake」仍差 **2 步天生不是模型能力**的步骤——无论 PT 加多少能力都补不上，因为它们是 IO/算力管线而非推理：

1. **① 下载（yt-dlp）**：从用户给的 URL 把原片拉下来。PT 是推理 API 网关，不会替你去爬 YouTube/TikTok/B站。
2. **⑥ 合成（FFmpeg）**：把生成的若干片段按时间线拼接、烧字幕、重排 9:16。这是 NLE 级剪辑，不是一次模型调用能解决的。

（⑦ 发布可砍，也可由网站后端调平台 API，同样不归 PT。）

→ 所以准确的说法是：**PT 补齐 5 类 = 接管 remake 的「大脑」（所有 AI 理解/改写/生成/转录），你只需在网站后端留「两只手」（yt-dlp 下载 + FFmpeg 合成）**。对"通过 PT 完成整个 remake"的诉求，这已经 100% 满足——剩下的下载/合成任何做视频网站的架构都必须自己跑，与 PT 有没有这些能力无关。

## 3. "没有 GPU"怎么破（修正后更轻松）

你这边**完全不需要 GPU**：
- ②③④ 理解/改写/转录 → 全走 **PT 云端**（chat + 多模态）。
- ⑤ 生成 → **PT 云端**。
- ① 下载（yt-dlp）、⑥ 合成（FFmpeg）→ 纯 **CPU** 开源工具，免费、许可证友好。

本地只剩"下载 + 合成"两个极轻的 CPU 步骤，**无 GPU 零压力**。比早期方案（还要本地跑 whisper/Qwen）简单得多。

## 4. 推荐架构（数据流，修正后）

```
用户链接
   │
   ▼
[① yt-dlp] 下载原片 ─────────────► 原视频文件
   │
   ├──────────────► [② PT 多模态chat] 吃音轨/片段 → 转录文案
   │
   ▼
[③ PT 多模态chat] 吃关键帧+片段 → 抽结构/风格/分镜
   │
   ▼
[④ PT chat] 据结构+风格改写新分镜脚本
   │
   ▼
[⑤ PT 视频生成] 逐镜生成新画面（Seedance/Kling/MiniMax/Wan）
   │
   ▼
[⑥ FFmpeg] 拼合 + 字幕 + 9:16 重排 ──► 成片
   │
   ▼
[可选 ⑦] 发布 / 仅提供下载预览
```

PT 出现在 **②③④⑤**（云端），开源只负责 **①⑥**（CPU）。

## 5. 开源"必须/兜底"清单（许可证友好，可商用）

- **必须**：**yt-dlp**（①下载，Unlicense）、**FFmpeg**（⑥合成，LGPL）。
- **兜底（可选）**：faster-whisper（②长视频转写更稳，MIT）、Qwen2-VL（③若不用 PT 多模态时，Apache2）。
- **规避项**：本地视频生成模型（CogVideoX-5B / HunyuanVideo 自定义商用条款）——我们走 PT 云端，绕开。

---

## 6. 必须和你说清的两点

1. **网站仍需一个轻量后端**：只为了跑 yt-dlp（①）和 FFmpeg（⑥）这两步。最便宜的 CPU VM（约 $5/月）即可；PT 的 chat/视频生成从浏览器或后端直接调云端 API（PT 私有控制台 API 甚至 CORS 全开，可做纯静态站点）。
2. **PT 按量付费**：生成（⑤）+ chat/多模态（②③④）都走 PT 计费。这是你"必须 PT"要求的必然代价；降本可选 PT 内便宜模型（Wan 最便宜，chat 用 flash 档）。
