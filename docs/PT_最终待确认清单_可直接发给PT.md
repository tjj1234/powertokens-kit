## A 组 · 生成链路错误处理（4 条，建议优先）

### A1 · 403 的两种原因如何区分（R2①）

**问题**：`403 Forbidden` 同时用于「Key 无该模型权限」和「模型已下架 / 未接入」。调用方如何在响应里区分这两种情况？请给出区分依据（`error.code`、`error.message` 关键字，或某个响应字段），最好各附一条脱敏响应体。

**为什么需要**：两种原因的处理方式完全相反——前者应换 Key 或申请授权，后者应换模型。我方错误字典需要把它们归到不同类别。

**不答的影响**：Agent 遇到 403 只能统一「停止」，无法给出正确的下一步建议。

**补充（第五批新发现的口径冲突）**：贵方第五批对比表第 8 行写「模型**不在上架列表** → `400` + `invalid_request` + `upstream_error` (middleware abort)」，但我方现有资料记录的是 `403` + `model_not_found ... not listed (pending)`，且该模型仍出现在 `/v1/models` 列表里。请一并说明：**400 与 403 分别对应哪些「模型不可用」场景**？（未接入 / 未上架 / 已下架 / Key 无权限 / 列表里有但未启用），以及每种的 `error.code` 与 `error.message`。这比我方原先只问「403 内部怎么区分」更关键。

> 已确认的背景：`401` = 凭据无效（`token_invalid` / `expired` / `disabled`）；`402` = 余额不足；`429` 按账户限流。这些**不用再答**。

### A2 · 流式「流中途失败」是否实际扣费（R10）

**问题**：在贵方第四批《汇总对比表》里，「流中途 scanner 错误 / streaming timeout / 客户端主动断」这三类是 **HTTP 200 已锁死 + SSE 末尾补发 `finish_reason=error|timeout|abort` + `[DONE]`**，并注明「**不会触发 controller 层 Refund；但 `adaptor.DoResponse` 内部已做 settle**」。

请确认：
1. 这三类请求**是否产生实际扣费**？如果产生，按什么计量（已产出的 token？预扣全额？固定值？）？
2. 它与「生成失败 → 同循环内全额 `RefundTaskQuota`」的边界是什么？后者是否**特指异步视频任务（Submit / Polling 链路）**？
3. 这类请求在消费记录里的 `status` 与 `quota` 长什么样？能否据此对账？

**为什么需要**：第三批答复让我方把「生成失败不扣费」记成了统一口径，而本批「内部已 settle」看起来是另一套结算。两者需要一条明确边界，否则扣费字段会写错。

**不答的影响**：Agent 可能把 HTTP 200 但 `finish_reason=error` 的响应当成成功，或盲目重试造成对账差异。
