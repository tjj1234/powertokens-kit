| **账户 / 计费 / 日志域** | `https://powertokens.ai/api` | **个人访问令牌 `pt_live_` + 32 位随机串**，账号级唯一、重生成需先移除旧的、明文仅展示一次 | D1:25-36、D4 §7 |
| **OAuth 域** | `https://powertokens.ai/api/oauth/*`（授权页在 `www.powertokens.ai/oauth/authorize`） | JWT `access_token`，供桌面软件 / 第三方登录；**会话凭证，不能用于 API** | D7、D4 §7 |

**D4 §7 一句话定稿**：
- 对外接口只用一种方式：`Authorization: Bearer pt_live_<token>`；
- 「access key + key id」是**渠道（上游）配置字段**，不是 PT 接口鉴权头，文档分节表格属**笔误**，PT 会修正；
- **不要做 AK/SK 双头**。

> ⚠️ **冲突 C1**：D1:28 写 `Authorization: {{access_token}}`（**无 `Bearer` 前缀**），D4 写 `Bearer pt_live_`。二者不能同时成立 → **必须真机实测裁决**（§7 T2）。另注意 D4 的「所有对外接口」应理解为其答复语境下的**账户域接口**，生成域仍按 D5 用 API Key，用户第 4 条「正常生成都不用改」亦印证。

> ⚠️ **冲突 C2**：用户此前「其他接口可以用 access key + key id」被 D4 §7 判为文档笔误。**以 D4 为准**，账户客户端不要实现 AK/SK 双头。

### 2.2 生成域错误码全表（D4 §1 + 第 5 批 + A.04）

**判定只看 `error.code`，不要看 message 文案（会随 i18n 变）。**

| 场景 | HTTP | `error.code` | `error.type` | 调用方处理 |
|---|---|---|---|---|
| 模型未上架 / 已下架 / 从未接入 | 403 | `model_not_found` | `api_error` | 换模型或提上架需求 |

| 已上架、但当前分组无可用渠道 | **503** | `model_not_found` | `api_error` | 找运营（**同 code，靠 503 区分**） |
| 请求体非法 / 未指定 model | 400 | `invalid_request` | `api_error` | 改请求 |
| 上游原始 400（参数不合法、上下文超限等） | 400 | 上游 code（多为 `invalid_request`） | `upstream_error` 或上游 type | 改请求，**不重试** |

**A.04 三分类（仍有效）**：`401` 凭据无效（`token_invalid` / `expired` / `disabled`）· `402` 余额不足 · `403` 权限不足或模型下架。

**`/v1/models` 列表与 403 的时延**：列表按「分组可用 + 命中定价规则 + status=2」三重过滤，status 走内存缓存每 60s（`SYNC_FREQUENCY`）刷新；后台直改 DB 状态最长滞后 60s。请求名带后缀（`-thinking`）、渠道映射名与列表名不一致，也会表现为「列表有、调用 403」。

### 2.3 失败场景 × 状态码 × 响应体 × 扣费（第 4 批 9 行，D4 补充）

| 场景 | HTTP | 响应体 | 扣费 |
|---|---|---|---|
| 非流式 上游 5xx（首包前） | 透传 502/503 | `application/json`，OpenAI error 格式，`message` 追加 request_id | 失败 → 自动 Refund |
| 非流式 DoRequest 超时 | 固定 500 | JSON `code=do_request_failed` | 失败 → 自动 Refund |
| 流式首包前 上游 5xx | 同非流式（透传 / 500） | JSON error，**不走 SSE** | 失败 → 自动 Refund |
| 流式首包前 DoRequest 超时 | 固定 500 | 同非流式 | 失败 → 自动 Refund |
| 流中途 scanner 错误 | **200（已锁死）** | SSE 末尾 `finish_reason="error"` + `[DONE]`；无 error 类型 event | **内部已 settle，按量扣费**（D4 §2） |
| 流中途 streaming timeout | 200 | `finish_reason="timeout"` + `[DONE]` | 同上 |
| 流中途 客户端主动断 | 200 | `finish_reason="abort"` + `[DONE]` | 同上 |
| 异步 Submit 上游 5xx | 透传上游状态码 | `TaskError JSON`, `code=fail_to_fetch_task` | `defer` 自动 Refund |
| 异步 Submit DoRequest 超时 | 固定 500 | `TaskError JSON`, `code=do_request_failed` | `defer` 自动 Refund |

### 2.4 「是否已被受理」判定与重试（D4 §3，R11 闭环）

**没有单一专用信号**，按组合判定，落成 4+1 条规则：

| 观察 | 结论 | 自动重试 |
|---|---|---|
| 非 2xx（401/402/403/429/5xx） | 一定没受理，费用已自动退回 | ✅ 可以 |
| 200 + JSON（非流式） | 已受理、已结算 | ❌ |
| 200 + SSE，末帧 `finish_reason=stop/tool_calls/length` | 正常完成 | ❌ |
| 200 + SSE，末帧 `finish_reason=error/timeout/abort` | **已扣费，中途失败** | ❌（会二次扣费） |
| 异步：200 + `task_id` | 已受理 | 用 task_id 查状态，**不要重复提交** |

`X-Oneapi-Request-Id` **只用于报障定位，不是受理信号**。

**429 补行**：`429` + `{"error":{"message":"您已达到请求数限制：N分钟内最多请求M次","type":"api_error","code":"model_rate_limited"}}`；上游 429 原样透传。**`Retry-After` 一定有**（网关默认 5s，上游给了用上游值）。网关侧限流发生在预扣费之前，不产生费用、无需退款；上游 429 属首包前失败，自动退款。属于「肯定没受理」，可安全重试。

### 2.5 扣费 / 退款 / 幂等（Q8 全链路，D4 §2 补齐边界）

- **预扣 → settle 是同一条链的两个出口**，不是两套账：
  - 非 2xx / 首包前失败 → **自动全额退款**（第三批「失败不扣费」指此）；
  - 200 已成型后流中途断 → `adaptor.DoResponse` 内部 **settle，按量扣费**。
- **流中途按「已计费输入 + 已产出输出」在中断时刻的实测 token 结算**；唯一例外：`total_tokens=0`（一个 usage 都没取到）按 0 结算，等于全额退回。
- **`RefundTaskQuota` 只服务异步任务**（video/image 的 task 表）；**同步 chat 链路从不走它**。
- 对账：流中途这类记录的 `status` **仍是 `success`**、`quota > 0`、`logs.other.finish_reason` = `error`/`timeout`/`abort`。**用 `finish_reason` 过滤，不要指望 status 变 failed——同步链路没有 failed 终态。**
- 异步任务失败：Submit 成功即已预扣 → polling 检测 FAILURE → 同循环内全额 `RefundTaskQuota`。
- 轮询超时：已预扣 → `sweepTimedOutTasks`（默认 24h）→ 标 FAILURE + 自动退款（**legacy 任务除外**）。
- 退费零延迟，DB 事务级同步退回（钱包 / 订阅 / Token 额度 / 专属积分同时退）。
- 防二次退费三重：`quota==0` 入口早退 + CAS 乐观锁 + 退费后持久化 `Quota=0`。
- `task_id` 复查完全安全：Fetch 端点只读（DB + 上游 FetchTask），不触发 Submit / Refund / Settle；不会重新生成、不会二次扣费。
- **legacy 任务**：`submit_time < 2026-02-22 00:00:00 UTC` 的旧系统迁移存量，只看提交时间；超时只置失败 + 提示联系管理员，**不退款**。
- `TASK_TIMEOUT_MINUTES` 默认 `1440`（24h），可配，`0` = 关闭，改值重启生效；sweep 每 15s 扫「未完成且已超时」补退款，**进程崩溃后重启能兜住**。唯一兜不住：预扣完成但 task 行未落库就崩（无任务记录，只能按日志人工排查）。
- 失败/超时任务写一条 `status=failed` 消费记录（`quota` = 预扣值），退款再写一条 refund 流水（负数），明细净额 0；**对账要看「消费 + 退款」成对出现、净额为 0**。

### 2.9 Seedance 双接口 / 产物有效期 / 协议（D5 + D4 §4 + C1/C2）

**双接口端点（D5 实锤，S1 闭环）** —— 两种接口**共用 Base URL `https://api.powertokens.ai`**：

| 维度 | 官方兼容接口（= 透传） | OpenAI 风格接口（= 标准） |
|---|---|---|
| 创建任务 | `POST /byteplus/api/v3/contents/generations/tasks` | `POST /v1/videos` |
| 查询任务 | `GET /byteplus/api/v3/contents/generations/tasks/{id}` | `GET /v1/videos/{task_id}` |
| 任务列表 | `GET /byteplus/api/v3/contents/generations/tasks` | 不支持 |
| 取消/删除 | `DELETE /byteplus/api/v3/contents/generations/tasks/{id}` | 不支持 |
| 参数结构 | 与字节官方一致（`content` 数组） | OpenAI 风格（`media` 数组） |
| 素材 | `"url": "asset://XXXX"`（相同） | 相同 |
| 鉴权 | `Authorization: Bearer <API_KEY>` | 相同 |

D4 C1 补充：透传是**独立前缀路由**（`/byteplus/v3/...`、`/minimax/...`、`/kling/...`、`/vidu/...`），**不是 `/v1/videos` 加参数**；鉴权仍是 Bearer；完整端点 + 字段差异清单待确认接入后由 PT 给对齐文档；**PT 建议走标准接口**。

**产物有效期（D4 §4，S2 闭环）**：
- **标准接口**：文件本体转存到 PT 对象存储，返回 **PT 自有地址**（视频 `/v1/videos/{task_id}/content`，图片同理），**不带签名、不设过期、需带 PT token 鉴权**。「永久保存」= 本体长期 + URL 长期可引用，**不需要强制「成功即转存」**；前提是任务记录保留（默认不清）。
- **透传接口**：24h 是**上游（BytePlus / 阿里 / 可灵 / Vidu）返回的签名下载链接**有效期，由上游在**生成完成时**签发、从生成完成起算；PT 透传不落盘，链接过期后**无法凭 task_id 重新签发**，只能重新生成 → **透传链路必须「成功即下载转存」**。

> ⚠️ **冲突 C4**：D5:476 写「视频 URL 有效期为 **14 天**，请及时下载保存。仅可查询最近 **7 天**内的任务」，且 D5:461 的示例 `content.video_url` 是字节 TOS 域名（`...volces.com/...`）而非 PT 自有地址。与 D4「标准接口永久 / 透传 24h」三个数字并存 → 很可能是**不同接口/不同版本**，需真机核验（§7 T5）。

**协议（S3 闭环）**：D4 C2 明确 **透传也需要签《Asset Library User Agreement》**，且仍强制 `asset://`；`asset://` 是上游账号维度素材体系，透传时素材仍挂在 PT 账号下、仍受上游协议约束。PT 建议走标准接口、素材上传由 PT 代理。

**本仓库协议处理现状（四层，第五批核实）**：
1. 数据：`kinds.seedance.requires` 声明需签协议 + media-text + 图生强制 `asset://`；
2. CLI：`seedance_agreement_signed` 本地标记 → 只提示不阻断提交；提交报错命中关键词 → 重置标记重新引导；生成成功即记为已签（`pt_video.py:944-982/1053/1076/1083`）；`seedance enable|disable|status`，`status` 有 Key 时 best-effort 真查 `GET /v1/asset/agreement/status`；
3. 素材：`force_asset=True` 时 `build_media()` 只收 `asset://`，外部 http(s) 直接拒绝；`upload` 传成 `asset://<id>`；
4. 隔离：Seedance 独立 kind，普通 `video` 的 auto 候选已剔除，须 `--type seedance`。

边界：**网关层无协议前置检查**（`pt_gateway.py` 里 3 处 `agreement` 只是 `account_query` 只读 action），走 MCP / 网关 REST 不会弹引导；`pt_video.py:945` 注释「PT 没有查询协议是否已签的 API」已过时。

**资产库（D6 / D5）**：三类资产（官方素材库 / 虚拟素材 / 真人素材）；两步拿到 `asset_id`——`① 上传素材 → task_id → ② GET /v1/asset/jobs/get-asset-id 轮询（此接口不需要鉴权）→ asset_id`；请求里一律 `"url": "asset://<asset_id>"`，**不能直接传外部 URL**。

### 12.1 凭证身份与域隔离

| 探测 | 结果 | 结论 |
|---|---|---|
| `Bearer <48 位串>` → 生成域 `GET /v1/models` | HTTP 200、全量模型（84 个） | **第二串是生成域 API Key** |
| `Bearer pt_live_...` → 生成域 `GET /v1/models` | 401 `token_invalid` / "Invalid token" | 生成域不接受个人令牌 |
| 裸 `pt_live_...` → 生成域 `GET /v1/models` | 401 `token_invalid` | 域隔离双向坐实 |
| `Bearer <生成域 API Key>` → 账户域 | `code=500 token not found` | 账户域不接受生成域 Key（与 §10.2 T7 一致） |

即：**两个域两套凭证** —— 生成域 `Bearer <API_KEY>`，账户域裸 `pt_live_`。

### 12.2 C1 裁决（本次核心）：账户域用裸值，不带 `Bearer`

| 端点 | `Authorization` | 业务 `code` / `msg` | 判读 |
|---|---|---|---|
| `/v1/asset/agreement/status` | 裸 `pt_live_` | **200**，返回账号协议状态 | ✅ 鉴权通过、返回真实业务数据 |
| `/v1/billing/balance?key_id=<数字>` | 裸 `pt_live_` | **200**，返回余额 | ✅ 鉴权通过 |
| `/v1/billing/balance?key_id=<数字>` | `Bearer pt_live_` | 500 `token not found` | ❌ 前缀导致 token 查找失败 |
| `/v1/logs/query?limit=1` | 裸 `pt_live_` | 500 `request_id / task_id / consume_id is required` | 已过鉴权，进入参数校验 |
| `/v1/logs/query?limit=1` | `Bearer pt_live_` | 500 `token not found` | ❌ 未过鉴权 |

**结论**：`Authorization: pt_live_<token>`（**裸值**）为账户域定稿；**D4 §7「所有对外接口只用 `Bearer pt_live_`」在账户域不成立**，D1:28 的裸值口径正确。
