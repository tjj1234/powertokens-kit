## 2. 「默认模块」4 个接口（本轮唯一实现依据）

| # | 方法 | 路径 | 用途 | 备注 |
|---|---|---|---|---|
| 1 | POST | `/v1/payment/create` | 创建支付订单 | 响应字段为**驼峰** `redirectUrl` / `orderNo` |
| 2 | POST | `/v1/billing/estimate` | 视频 / 图像模型费用预估 | 官方 2.0.0 也确认存在；**仅视频/图像**，不含 chat；`calculation` 明写 `1000 quota/USD` |
| 3 | POST | `/key/info` | 获取 Key 信息 | **路径没有 `/v1`**（与 2.0.0 规划稿的 `GET /v1/key/info` 不同） |
| 4 | POST | `/v1/logs/list` | 消费记录批量查询 | **`page` 分页**，不是 cursor；与 2.0.0 规划稿「正文 GET / 附录 POST」自相矛盾处不同 |

公共响应：`{ code, data, msg }`，**业务判断以 `code` 为准**（v1.0.0 口径）。

### 2.1 必须记住的 5 个实现坑

1. **`data` 是字符串化 JSON**：拿到后要二次 `json.loads(data)` 才是对象；
   直接 `resp["data"]["xxx"]` 会 TypeError。
2. **`/v1/logs/list` 用 `page` 分页**，不是 cursor / offset；默认页大小与上限待核对。
3. **驼峰与 snake_case 混用**：`redirectUrl` / `orderNo` 与同组其他字段命名不一致，
   反序列化后别只按一种命名取值。
4. **`/key/info` 无 `/v1` 前缀**：路径拼接时不要统一加 `/v1`。
5. **`client_operation_id` 已不存在**：不要再生成 / 透传该字段，也不要把它写进 `charging`。
